[ CONQUEROR BRIDGE ]

DEVELOPER BRIDGE - NO AUTHENTICATION. Anyone on this network can drive the tank (page, WebSocket, TCP 3333). Use it only on your home network. Never in release firmware.

The source archive does not match this firmware (the app was updated over WiFi without the source image). Run scripts/ota.sh or flash over USB.

[ DRIVE ]

  • Phone: open / - joystick (release = stop), big STOP, speed slider, camera stick (returns home). One driver at a time; others see "Busy". STOP works from every page. The IR remote beats everyone.
  • Bench tool (laptop): uv run bench -H conqueror-bridge.local dash (finds the bridge with bench discover). The bench is refused while a phone drives.
  • Phone asleep or page closed: no more drive messages → the Uno stops within 0.3 s (deadman).

[ REFLASH ]

ESP32 (this board)

cd firmware/esp32
python3 scripts/check_chip.py --port /dev/ttyACM0      # refuses anything but ESP32-S3 / 8 MB / 8 MB PSRAM
pio run -e bridge -t upload --upload-port /dev/ttyACM0  # bootloader + partitions + app (chip check runs first)
pio run -e bridge -t upload_source --upload-port /dev/ttyACM0   # source archive at 0x610000
CQ_OTA_PASSWORD=... scripts/ota.sh                      # over WiFi: app + source (only while nobody drives)

Release binaries: GitHub releases bridge-vX.Y.Z with flash.sh. Hold BOOT while plugging in if no port appears.

Uno (body)

Shield switch S1 to "upload" (disconnects the ESP32), then:
cd firmware/uno && pio run -e uno -t upload    # USB only, Optiboot 115200
S1 back afterwards.

The Uno is never updated over WiFi.
